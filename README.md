# AudioCurve

Системный 3-полосный эквалайзер для джейлбрейка с экраном в стиле AirPods Custom EQ из iOS 26/27.

Важный момент про оригинал: экран, который ты скинул, — это **Custom EQ для AirPods**, и сама обработка там живёт в прошивке наушников. Повторить её нельзя. Поэтому здесь сделано другое: тот же интерфейс, но фильтр вешается на **микс всей системы внутри `mediaserverd`**. То есть эффект работает на любом источнике — Apple Music, Spotify, YouTube, Safari, Telegram, игры — и на любом выходе: динамик, проводные, AirPods, Bluetooth-колонка.

## Скачать готовый .deb

Каждый пуш в `main` собирает пакет в GitHub Actions:

1. вкладка [Actions](../../actions) → последний запуск `build`
2. внизу страницы блок **Artifacts**
3. `AudioCurve-rootless` (Dopamine, palera1n rootless) или `AudioCurve-rootful` (unc0ver, checkra1n)

Внутри zip лежит `.deb`: распаковать, открыть в Sileo, установить, сделать респринг.

## Что внутри

```
AudioCurve/
  Makefile              сборка твика + подпроекта App (rootless)
  control               метаданные пакета для Sileo
  AudioCurve.plist      фильтр: mediaserverd + SpringBoard
  Tweak.xm              хук AudioUnitRender, кэш аудиоюнитов, метрика, IPC
  eq_dsp.c/.h           RBJ-биквады: low shelf 110 Гц, peak 1 кГц, high shelf 6.5 кГц
  ac_meter.c/.h         8 band-pass фильтров + детектор огибающей для волны
  ACShared.h            общий контракт: ключи notify и упаковка в uint64
  tests/test_dsp.c      хостовые тесты DSP (запускаются на маке/линуксе)
  App/                  приложение с интерфейсом 1:1 со скринов
```

## Как это работает

**Обработка.** `%hookf` на `AudioUnitRender` в `mediaserverd`. После вызова оригинала буфер уже содержит смикшированный PCM, и по нему проходит каскад из трёх биквадов. Юниты кэшируются по указателю: роль (`Mixer` / `Output`) определяется один раз через `AudioComponentGetDescription`, формат — через `kAudioUnitProperty_StreamFormat`. Поддержан Float32 и int16, interleaved и planar. В render-треде нет ObjC, аллокаций и блокирующих локов — только `os_unfair_lock_trylock` на метрике.

**Настройки.** Приложение пакует «вкл + 3 гейна + режим» в один uint64 и кладёт его через `notify_set_state`. `mediaserverd` читает состояние по дарвин-нотификации. Никакой возни с песочницей и без RocketBootstrap. Плист остаётся для персистентности, а хук в `SpringBoard` переопубликовывает его после респринга/ребута.

**Волна.** В `mediaserverd` считается моно-даунмикс, прогоняется через 8 band-pass фильтров (60 Гц … 8 кГц) с огибающей 12/220 мс, упаковывается в uint64 и публикуется ~30 раз в секунду. Приложение читает это по `CADisplayLink`. Поэтому полоски реагируют на звук из **любого** приложения, а не только из своего процесса.

**Now playing.** Через `MediaRemote` (dlopen), так что название, артист, обложка и кнопка play/pause работают с любым плеером, включая Spotify и YouTube.

**Интерфейс.** Строки Recommended/Custom с галочкой, сноска, карточка трека, зеркальная волна с градиентом (тёплый низ → холодный верх), пунктирные ориентиры LOW/MID/HIGH, затемнённая колонка активной полосы, кривая Catmull-Rom с тремя точками ±12 дБ, хаптик при переходе через 0 дБ, «Reset», в простое — пунктирная линия как на третьем скрине. Тёмная тема через системные цвета.

Полоски дополнительно масштабируются реальной АЧХ фильтра: поднял низ — левая часть волны стала выше. Кривая рисуется не «на глаз», а по фактической передаточной функции тех же коэффициентов, что крутятся в `mediaserverd`.

## Сборка

```bash
export THEOS=~/theos
cd AudioCurve
make dsptest                 # прогнать тесты DSP (необязательно, но полезно)
make package FINALPACKAGE=1  # .deb появится в ./packages
```

Установка на устройство:

```bash
export THEOS_DEVICE_IP=192.168.1.50   # свой IP
make package install FINALPACKAGE=1
```

Или закинуть `.deb` из `packages/` в Sileo. После установки — **респринг** (перезапуск `mediaserverd` подхватывается автоматически, но респринг надёжнее).

Для rootful-джейлбрейков (unc0ver, checkra1n) собирай так:

```bash
make package THEOS_PACKAGE_SCHEME= FINALPACKAGE=1
```

Тесты DSP, если хочется вручную:

```bash
cc -O2 -I. -o /tmp/ac_test tests/test_dsp.c eq_dsp.c ac_meter.c -lm && /tmp/ac_test
```

У меня они проходят все: +6 дБ на low shelf дают +5.6 дБ на 50 Гц и 0.00 дБ на 12 кГц, -8 дБ на миде дают ровно -8.00 дБ на 1 кГц, при +12 дБ по всем полосам пик 0.999 без NaN, метр правильно ловит 1 кГц.

## Если эффекта не слышно

Граф аудиоюнитов в `mediaserverd` немного отличается между прошивками, поэтому есть переключатель цели. Правь плист:

```bash
# 0 auto (по умолчанию), 1 только микшер, 2 только output-юнит, 3 оба
plutil -replace targetMode -integer 1 /var/mobile/Library/Preferences/com.sa1nt.audiocurve.plist
plutil -replace verbose -bool true /var/mobile/Library/Preferences/com.sa1nt.audiocurve.plist
killall -9 mediaserverd
```

С `verbose` в лог пишутся все юниты с их 4CC-типами:

```bash
idevicesyslog | grep AudioCurve
```

По логу видно, какие юниты реально проходят через хук, и можно выбрать `targetMode` под свою прошивку. Строка статуса в самом приложении показывает, отвечает ли `mediaserverd` вообще.

## Честные ограничения

- Это **не** замена прошивочного EQ AirPods. Apple считает свой Custom EQ в самих наушниках, доступа туда нет. AudioCurve обрабатывает звук до отправки на выход, результат похожий, но механика другая.
- `targetMode` может потребовать подгонки: на разных версиях iOS финальный узел графа отличается.
- Пространственное аудио и Dolby Atmos обрабатываются своими цепочками, эффект на них может быть слабее.
- Если `MediaRemote` не отдаёт трек, приложению нужна подпись с энтайтлментами (`ldid -S`) или запуск от root — карточка трека тогда просто пустая, эквалайзер продолжает работать.
- Обработка добавляет ~15 биквадов на канал на блок. На A12+ это меньше процента ядра, но на старом железе с очень маленьким буфером стоит проверить отсутствие дропаутов.
- Тесты прогоняются только для C-ядра. ObjC/UIKit-часть без iOS SDK и Theos локально не компилируется — первую сборку делай на маке или в Actions.
